1Browser → Route 53 → CloudFront
2Static JS/CSS from S3 via CloudFront
3SPA bootstraps → Cognito JWT refresh
4API GW REST → ALB → Dashboard Service
5Dashboard Service → ElastiCache (cache hit)
6Cache miss → RDS Read Replica
7Response → ALB → API GW → Client

1External data source → Kinesis Data Streams
2Stream Processor Lambda consumes events
3Aggregation computed → DynamoDB + ElastiCache
4Widget Service polls ElastiCache (30s TTL)
5Widget Service pushes update via WebSocket API GW
6Connected clients receive update instantly
7Firehose writes to S3 → Glue catalog

2Lambda renders dashboard via headless Chrome
3PDF/PNG uploaded to S3 (private bucket)

4CodeDeploy: Blue/Green ECS task replacement

Senior Engineering Design Decisions
Multi-Tenancy

Shared infrastructure, tenant-isolated data via row-level security in RDS (tenant_id column) and separate DynamoDB partition keys. Cognito custom scopes enforce API-level isolation.

Caching Strategy

Cache-aside pattern — services check ElastiCache before DB. Widget data TTL is configurable per widget (15s–5min). CloudFront caches API responses for non-personalised endpoints.

Auto-Scaling

ECS Service Auto Scaling on CPU (70%) + custom metric (SQS queue depth). Scale-out before market open, scale-in overnight. Lambda handles bursty workloads with no pre-provisioning.

High Availability

All stateful components (RDS, ElastiCache, NAT GW) deployed across 3 AZs. RDS Multi-AZ auto-failover <1 min. Route 53 health-check failover to DR region for critical outages.

Security Posture

Zero-trust network: all services in private subnets, outbound via NAT only. Least-privilege IAM task roles, secrets in Secrets Manager, all data encrypted KMS CMK.

Cost Optimisation

Athena + S3 Parquet is ~80% cheaper than a persistent Redshift cluster for ad-hoc analytics. Spot instances for non-prod. Kinesis on-demand mode avoids over-provisioning shards.
